# Kanbi v0.3.0-beta.3

Kanbi `v0.3.0-beta.3` adds global Focus Mode, project-file completion, and safer session repair while consolidating lifecycle rules shared by the TUI and CLI. This remains beta software, not a feature-complete or stable `v1.0.0` contract.

## Changes since beta.2

- Add opt-in Global Focus Mode across every unarchived board. Configure it with `F`, choose the workflow keys that consume capacity, and set a global commitment limit.
- Require durable pause checkpoints with a reason, completed work, and exact next action. Checkpoint history is append-only, and resume can send the structured handoff back to the agent.
- Serialize Focus Mode admissions in SQLite, support atomic replacement at capacity, and expose provider-driven overflow without discarding authoritative remote transitions.
- Add `@` project-file completion to ticket bodies and notes. Search uses the ticket worktree when one exists, otherwise the board directory, and inserts a textual relative path without attaching file contents.
- Show an existing verified harness session ref as a tab-accessible field in the ticket editor so it can be corrected without rewriting session history.
- Submit Pi's initial positional prompt explicitly for Pi versions that populate the editor without starting the turn.
- Standardize single-line editing and preserve bounded cursor, viewport, scrolling, and selection state across ticket, board, filter, integration, focus, and repair modals, including 80-column layouts and live resize.
- Retry Herdr's transient `agent_pane_busy` response during pane initialization, choose safer split anchors, and focus only after launch succeeds.
- Schedule and drain owning-board provider sync after CLI ticket creation, update, movement, and note addition. Provider-backed CLI mutations may therefore update remote GitHub or Jira records before the command exits.
- Harden backup restore and board-package preview/import through shared archive checks that reject non-regular, traversing, oversized, backslash-path, symlinked, or invalid imported data.
- Keep repository integration readiness and completion bound to authenticated reports; native and transcript runtime observation can project attention states only.
- Route CLI ticket mutations and archive validation through shared application/storage seams, and centralize runtime-state semantics so supported command surfaces enforce the same lifecycle rules.

## Included beta surface

- Local, GitHub Issues, and Jira boards, plus a synthetic multi-board Master view.
- tmux as the default runtime and opt-in Herdr support.
- Start, focus, close, repair, start-fresh, and verified resume flows for supported harnesses.
- Optional per-ticket Git worktrees and agent-assisted repository integration.
- Board archive, sync controls, portable board packages, and full database-plus-attachment backup/restore.
- Redacted diagnostics, `kanbi doctor`, and support bundles.
- Native CGO-enabled archives for Linux and macOS on amd64 and arm64 with checksums and build provenance.

## Important missing features and limitations

- Kanbi remains beta software. The broader stable-readiness roadmap, multi-day operational soak, accessibility/usability matrix, and external-user qualification are incomplete.
- There are no Homebrew, distro, or Windows packages. Install a native archive manually; Windows and other Unix platforms are unsupported.
- Real Herdr, harness, GitHub, and Jira behavior depends on locally installed/authenticated third-party tools and services. Deterministic adapters are automated, while some real-service combinations remain opt-in/manual qualification.
- Harness resume depends on Kanbi capturing a verified harness-native session reference. If capture is unavailable, use the ticket repair screen to enter a verified ref or start fresh. The normal ticket editor can update an existing ref, but there is no separate non-interactive session-ref management command.
- Focus Mode workflow keys are configured globally and remain free-form; provider sync may temporarily exceed the limit because remote workflow transitions remain authoritative and must be resolved through checkpointed pauses.
- Git-worktree mode is a durable board policy after workspace history exists. Create a separate shared-directory board rather than attempting to disable it.
- Master workflow keys have no synonym mapping. Map mismatched columns explicitly with `kanbi boards set-column-key`.
- Board-package import does not rewrite every absolute attachment link in ticket Markdown, and merge-import is not supported.
- Jira smoke cleanup depends on project permissions; provider synchronization never deletes remote issues as part of normal local archive/delete flows.

Report problems through [GitHub Issues](https://github.com/carlotran4/kanbi/issues). Report vulnerabilities privately as described in [SECURITY.md](https://github.com/carlotran4/kanbi/blob/master/SECURITY.md).

## Install

1. Download the archive for your OS/architecture and `SHA256SUMS` from this release.
2. Verify the checksum before extracting.
3. Install `kanbi` into a directory on `PATH`.
4. Run `kanbi version` and `kanbi doctor`.

Full instructions: [docs/installation.md](https://github.com/carlotran4/kanbi/blob/master/docs/installation.md).

## Migration and rollback

This artifact uses database schema 8. Opening a schema-7 Kanbi database applies a forward-only migration that adds Focus Mode pause state and append-only pause checkpoints. Existing tickets, sessions, notes, workspaces, integrations, and provider identities are preserved.

Before upgrading:

```bash
kanbi backup "$HOME/kanbi-pre-v0.3.0-beta.3.kanbi"
```

Do not downgrade a migrated database in place. To roll back, stop Kanbi processes, reinstall the prior binary, then restore the backup created by that prior binary:

```bash
kanbi restore "$HOME/kanbi-pre-v0.3.0-beta.3.kanbi" --force
```

Changes made after that backup will be lost. Keep the prior binary and backup until the beta has been exercised.

## Support and security

The latest published beta receives best-effort fixes and security updates; older betas may be superseded without backports. Diagnostics logging is off by default. Inspect any redacted support bundle before sharing it, and never attach a full Kanbi backup to a public issue because backups contain private board data.
