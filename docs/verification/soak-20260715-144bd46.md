## Defect found and corrected before the passing run

An earlier candidate (`1fb27e9`) exhausted the original 4 GiB container memory and 1 GiB swap. Corrected monitoring showed the retry growing to 10.9 GiB process RSS and 12.38 GB cgroup memory in about 29 minutes before its safety abort.

Diagnosis found that every `ScheduleBoardSync` call launched a goroutine. Once the fake backend's bounded start channel blocked the active per-board sync, scheduling requests accumulated as thousands of goroutines behind the per-board lock; race instrumentation amplified their memory cost.

Commit `144bd46` coalesces mutation-triggered requests per board into one active worker plus at most one follow-up sync. Regression coverage submits a scheduling storm, verifies bounded goroutine growth and exactly one follow-up, and exercises concurrent shutdown. The passing run above used that exact fix commit.
